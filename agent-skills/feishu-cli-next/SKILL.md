# Feishu CLI Next

Use `feishu-cli-next` for Feishu/Lark workspace operations. All inherited commands, generated OpenAPI methods, raw API access, events, and domain skills remain available. Start with a known command; discovery, help, and authentication checks are for missing information, not prerequisites to every operation. Use guidance already provided; read additional references for a specific missing syntax or workflow detail. Combine independent reads or help lookups in one shell tool call when useful. Keep dependent operations ordered and guard subsequent steps with successful exit status, parsed JSON `ok`, and required resource IDs; stop and reconcile on failure.

## Common routes

The forms below follow the executable name; replace placeholders with the task's actual inputs. Use the identity authorized for the task. These are starting routes, not a restriction on other commands or compositions.

| Intent | Direct route and decision |
| --- | --- |
| Known user ID | `contact +get-user --user-id <id> --user-id-type open_id --as user` (also supports `--as bot`; match the ID type). For several known open IDs under user identity, `contact +search-user --user-ids <id,id> --as user`. |
| Find people or bots | `contact +search-user --query <keyword-or-email> --as user`; `contact +search-bot --query <keyword> --as user`. Check returned discriminators to resolve same-name matches. `has_more=true` requires refining the query/scope; these searches do not paginate. |
| Read a document | `docs +fetch --doc <URL-or-token> --detail with-ids --as user` returns native XML in `data.document.content` with block IDs; use the task's authorized identity. For fact/block-ID questions, read stdout and answer from that result when sufficient. Use `simple` for text only, `full` for styles/edit metadata. Save artifacts when requested or the result is large; consult read guidance for unfamiliar structures, scopes or incomplete results. |
| Edit document text | Read `full`, then `docs +update --doc <doc> --command str_replace --doc-format xml --pattern <exact-text> --content <replacement>`. For one occurrence, choose the smallest span established unique across the document, leaving unchanged styled text outside the match. If the match includes styles or links, preserve their actual fetched XML attributes and change only intended characters; Markdown markers are not XML formatting. For nonunique, multiline or structural edits, inspect `docs +update --help` for addressed `block_*` operations. Verify text, styles and link destinations after writing. |
| Import supplied Markdown | `docs +create --doc-format markdown --content @./source.md --as user` imports the existing file directly; `--title` and a parent destination are optional. Preserve the source file and verify native content with `docs +fetch --doc <returned-id> --detail full`. Use the authoring guide for composing new content or unfamiliar rich structures. |
| Read/update known Base rows | `base +record-get --base-token <base> --table-id <table> --record-id <id> --format json` (repeat `--record-id`). Check `base +field-list` if types/writability are unknown. For one existing row, `base +record-upsert --base-token <base> --table-id <table> --record-id <id> --json '{"<field>":<value>}'` updates only that ID; omitting the ID creates a row. For several rows, `base +record-batch-update` takes the base/table flags and `--json '{"update_records":{"<id>":{"<field>":<value>}}}'`. Submit only intended fields; preserve JSON null, zero and false. Optional `--skip-unchanged` compares submitted cells first. Verify affected IDs after writing; for unknown outcomes, read back before considering a retry. |
| Export exact sheet cells | `sheets +data-export --spreadsheet-token <token> --sheet-id <id> --range <A1-rectangle> --save-result ./cells.json` preserves native types, formulas, number formats and field presence. The CLI validates paired raw/formula reads, matching revisions and the complete rectangle before saving. For export-only tasks, check successful status and the returned complete artifact reference; inspect cells locally only when the answer needs values or diagnosis. CSV is a separate, potentially lossy conversion. |
| Transfer Drive file bytes | `drive +upload --file ./source --folder-token <folder> --as user` returns `data.file_token`; `--name <name>` overrides the source basename. Omit the folder for the caller's root. After confirmed success, use that token in `drive +download --file-token <token> --output ./download --as user`. Parse JSON and compare local bytes/hashes in ordered, success-guarded steps without printing file bodies. Existing files require explicit overwrite intent; document content operations belong to Docs. |

## Look up only what is missing

For additional flags or command-specific guidance, read the selected command's `--help`. For an unknown command, `discover "contact open_id" --flags --limit 3` matches every keyword literally against paths, aliases, descriptions and public flags; use short keywords and widen the result window only if needed. Explore a known domain with `<domain> --help`. `schema` supplies API input shapes; `api` permits custom OpenAPI requests. Names beginning with `+` are workflow shortcuts.

Read a specific domain reference only when its concepts, syntax or limitations are needed: `skills read <name> [path]`; `skills list` locates other domains. Retained examples say `lark-cli`; invoke `feishu-cli-next`. Docs uses `lark-doc` (references `lark-doc-update.md`, `lark-doc-xml.md`, `lark-doc-create-workflow.md`). Base complex cell values use `skills read lark-base`; formula/lookup field definitions require the guide acknowledgement described by `feishu-cli-next skills read lark-base references/lark-base-field-formula.md` and `feishu-cli-next skills read lark-base references/lark-base-field-lookup.md`. All other retained skills remain available on demand.

## Preserve results and intent

`--as user` and `--as bot` have different permissions. Follow concrete errors for missing authentication/scopes; `auth status` inspects login and `auth login` requires the user's browser participation. Native resource IDs differ by type; resolve ambiguity before sending, sharing, assigning, or changing a resource. Preserve the user's audience and destination.

Prefer offered file/stdin flags for substantial content. Keep document structure/reference maps, sheet formulas/types, and Base schema semantics. Omitted fields preserve data where supported; null, empty text, zero and false are distinct. Whole-document overwrite can lose unrelated blocks, IDs and comments; use it only for an intended full replacement.

JSON is compact without dropping fields. Read small responses directly from stdout when their contents are needed for the answer. Where supported, use `--save-result PATH` when the task requires a saved artifact or the response is large; it saves the full response without replacing an existing file. `--result-fields` selects fields while retaining status/completeness metadata; select only when omitted data is unnecessary for the task and verification. `--result-detail` adds indentation. Command-specific `--fields`/`--detail` retain their own meanings.

Check `ok`, exit status, pagination, warnings and partial-failure receipts; success need not contain OpenAPI `code`. A mutation timeout can leave an unknown effect: reconcile the affected resource or use documented backend idempotency before retrying a create, append, send or other non-idempotent write. Local receipts and readbacks do not provide a concurrency lock.
