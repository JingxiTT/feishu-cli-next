## Explicit interface changes

Thirteen command nodes are additions: `discover`, `guide` and its four lifecycle
subcommands, `receipts` and its three subcommands, `base +record-import`,
`sheets +data-export`, and `sheets +data-import`. Root flag additions are
`--profile`, `--result-detail`, `--result-fields`, and `--save-result`. The three
output controls default to false/empty and remain opt-in.

There are 27 changed metadata paths per brand, mapped individually in the
[source review ledger](p3-source-review.json):

- Ten shortcuts add `--skip-unchanged`: Apps update; Base batch update and
  upsert; IM chat update and message edit; Minutes summary, todo and update;
  Slides update and slide update. Existing Cobra flag contracts are unchanged.
- Twelve paths describe conditional bot/user read scopes for Apps, Minutes and
  Slides comparisons. The original write-only default must remain usable.
- Three validation hooks are added to Docs search, Task create and Tasklist
  create; local invalid input must fail before backend writes.
- Approval approvals search and Attendance user_tasks query become read-risk
  commands only in next mode. Their exact known POST query paths, service/method
  identity and original write risk must all match the narrow annotation helper.
  Frozen catalog risk and legacy annotations remain unchanged.

During review, Apps update was found to require an unconditional GET before its
original PATCH, narrowing write-only permissions and understating dry-run.
Commit `45b0be1` fixes this: default is PATCH only; explicit `--skip-unchanged`
adds the read scope, GET, exact app-ID validation and conditional PATCH preview.
`TestAppsMetadataWriteOnlyPathAndOptionalReadPreview` passed while its GET
handler would deny the read. Independently recounted evidence records 1,542 Apps
unit events, 123 inherited selected E2E events and 241 process events passing,
with one explicit live skip. The related schema/service/affordance check has 294
passes. This resolves the observed permission regression; it does not certify
live platform permissions.

## Review use and limits

The ledger binds each of 177 changed paths to both SHA-256 hashes, the exact
patch hash from the byte-verified import commit `0c1ac75`, changed functions,
owner reports, nearby tests and process tests. Every checkpoint source hash matches
the exported hash. Later working Apps upload/publication edits are recorded
separately as pending review and are outside this immutable checkpoint. It separately lists 36 new Go implementation dependencies,
which still require review even though they have no frozen counterpart.
Entries remain pending explicit review; there is no source whitelist or checker
acknowledgement mechanism. New hashes require renewed review.

The ledger links the full isolated race-run evidence at its earlier tested
revision `3218305`; it does not apply that run automatically to later patches.
It also independently recounts all 11 passing Sheets-to-Base integration events
after the final importer/journal corrections. That process suite covers the
10,000-row primitive artifact handoff and its documented failure cases; other
cross-domain workflows remain separate acceptance work.
