# P1 candidate surface reconciliation

Run the candidate check explicitly with:

```sh
python3 scripts/next_inventory.py check --surface next --target .
```

The captured result in `p1-next-reconciliation.json` compiles real candidate
registrations with `WithAgentMode()`, matching `main.go`. Both Feishu and Lark
candidate trees contain 948 nodes against the frozen reference's 938. No existing
command, flag, shortcut schema, generated catalog identity, or event schema was
removed or changed in that comparison. Ten command nodes were added per brand:
`discover`, `guide`, `guide show`, `guide install`, `guide update`,
`guide uninstall`, `receipts`, `receipts list`, `receipts inspect`, and
`receipts cleanup`.

Three inherited output controls are additions: `--result-fields` defaults to an
empty string, `--result-detail` defaults to false, and `--save-result` defaults to
an empty string. Projection, expanded formatting, and result artifact creation
are therefore opt-in. Existing domain flag names and defaults remain available.
The next distribution enables its compact JSON rendering; the legacy embedding
surface keeps its existing output contract. Registration equality does not
itself verify content preservation or every runtime output path.

The `guide` lifecycle commands add project-scoped installation, update and removal
of the concise English agent skill. Their presence is registration evidence;
installation collision, preservation and path behavior need the foundation and
packaging process tests.

An intentional semantic difference does not appear in registration metadata:
`update --check` reports `update_channel: unconfigured` and an ordinary `update`
returns a failed-precondition error instead of updating from the upstream npm
package. The candidate has no next release channel yet. **P4 packaging/update
parity remains open.** The update command's unchanged flag surface must not be
mistaken for completed self-update parity. The targeted regression is
`cmd/agent_test.go::TestAgentUpdateDoesNotUseUpstreamChannel`.

The candidate report retains registration evidence at `acaa67675f7a5f6341951481e55f9c72d61f668b` and lists 22 changed reference source files after the separate source-only refresh with exact reference
and candidate SHA-256 hashes. They remain `changed_source_requires_review`; this
