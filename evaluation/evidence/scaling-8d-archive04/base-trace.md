# Base size command-choice observations

The complete27-attempt Base phase verified25 outcomes and retained both nonverified Next attempts and all their provider costs. Both nonverified attempts have the fixed request_outside_fixture reason. The exact rejected requests and backend receipts were discarded; this reason alone cannot identify a product bug, an unsupported valid strategy, or the final contents of an otherwise correct import.

At100 rows, Next used13–25 shell executions and4–7 help-bearing CLI choices; the original used7–11 executions and1–2 help choices, and the concise original9–13 executions and1–3 help choices. At1,000 rows, Next used9–18 executions and3–8 help choices, compared with8–11 executions in each original arm. The two nonverified Next attempts also contain more failed shell/CLI steps than most verified runs. Their costs stay in the all-attempt distribution and efficiency denominators.

At10,000 rows, all nine attempts verified the complete native typed import and unchanged source/schema/sentinels. Next used9–11 shell executions, the concise original exactly11, and the original8–19. The original's highest-token trial also has19 shell executions and two recorded record-list choices; its372,564-token observation is retained as observed variation. The three Next trials together made175 backend requests, versus311 for the concise original and347 for the original. These totals include identity and all business requests, without selectively subtracting validation work.

The trace vocabulary is pinned to the reference command registry, with a small declared extra set. New Next import leaves can therefore appear only as the recognized Base prefix; scripts are categorized as scripts without instrumenting their child CLI calls. The trace cannot identify every exact import command or count all internal invocations. Source arguments, payloads, file contents and exact query values were discarded. Help/reference steps can contribute accumulated context, but provider accounting is per user turn and cannot assign token cost to an individual command or response. These observations explain concrete workflow differences without treating correlation as a complete causal account.

The three size points and three repetitions show descriptive variation only. They do not establish an asymptotic token bound, a universal reduction, or a performance claim for live data. File/interoperability and guidance choices are part of the declared task condition, and historical stopped fixtures remain separate.
